# Customer dialogue popup

Approved format: a compact, flat transcript with customer name/contact status, original customer time and speech, our exact messages, separately confirmed enterprise-WeChat cards, completed actions and next step. Explicit close at the top right; full record and acknowledgement fixed at the bottom. Window height follows content; long transcripts scroll. No example conversations or invented times in real notifications.

Stage navigation: P0 diagnose → P1 implement → P2 verify/audit → P3 background update.

## Implemented and verified

- P0: legacy placeholder strings hid an existing saved customer quote. Contact-only notifications could lack a database conversation timeline. Fixed the fallback and preserved newly observed original message ID/time in future contact notifications, without synthesizing inbound events or changing sending rules.
- P1: replaced the oversized summary with the approved flat dialogue layout, native rounded corners and visible close/record/acknowledgement controls. Removed fixed-height blank space. Record expansion displays the retained transcript and provenance details; footer remains visible. Compact mode retains the latest customer quote.
- P1: merge up to ten retained customer messages and ten outbound records by reliable platform time. Preserve separately observed speech by original native ID; missing time remains missing. A reply enters the completed summary only when the original turn contains the customer's message ID, original submission follows that message and the platform receipt confirms it. Old intents confirmed late receive no new-reply credit.
- P1: close persistently hides the current backlog without marking it read. ACK requests preserve multiple rapid acknowledgements and are restored on startup. No customer send is triggered by these controls.
- P2: Node suite 209/209 passed. Swift model regression passed. Native AppKit controls tested offscreen with real action dispatch in an isolated temporary runtime: compact layout, fixed controls, expand/collapse, persistent close, queue/ACK separation, multiple ACK preservation, pending ACK reload, long transcript scrolling. No desktop clicks, focus changes or production ACKs were used.
- P2: original customer card rendered with the compiled native UI and its unchanged saved queue data. Existing missing timestamps and missing program-send records remain explicitly identified. Preview renders do not display a window; an absent requested card exits without entering normal notification mode.
- P2: independent review and Red Team reproduced ordering/identity attribution defects; regression tests failed before each correction. Final review found no remaining release blocker within this scope.
